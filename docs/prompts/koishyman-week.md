## Приоритет и приёмка

**3–4 ноября: управление по MVP.**

- `/management`: связанный вход в подразделы; существующий каталог и форма предмета без регрессий.
- `/management/groups`: демосписок групп, программа и курс; форма или локальный предпросмотр группы. Не создавай серверных записей.
- `/management/semesters`: список семестров и понятные UI-состояния формы. Поля подписаны, некорректный ввод объясняется.
- `/management/study-plans`: связь группы, семестра и предметов с кредитами; локальный предпросмотр плана, без публикации и изменения личных оценок.
- `/management/users`: демопользователи, роли, назначенные группы модераторов. Правки отображаются только как локальный пример; серверные права не меняются.
- `/management/history`: ясно обозначенный демонстрационный журнал действий с датой, автором и описанием. Не выдавай его за настоящий аудит.

README определяет границы ролей: модератор работает в назначенных группах; администратор создаёт группы и назначает роли. Общий демокаталог не означает настоящую проверку доступа. Если показываешь административный вариант, явно подпиши его как пример. Пользователь не получает возможность назначить себе административную роль.

**5–6 ноября: UI будущих этапов.**

- `/management/moderation`: деможалобы, контекст сообщения и состояния рассмотрения. Локальная отметка или предпросмотр решения не удаляют сообщения и не блокируют пользователя.
- `/management/competitions`: примеры правил, срока, задания и проверки результата; интерфейс для будущей публикации. Реальных соревнований, начисления баллов и наград нет. Баллы за условные проверяемые задания, а не рейтинг по личному самостоятельно введённому GPA.

Каждый подраздел связан с `/management`; обратные ссылки и действия понятны. URL фиксированные: не вводи динамические ID, backend-маршруты и неподтверждённые возможности этапа 7.

## Общий стиль и данные

Русский интерфейс; белый с чёрным и нейтральным серым, Tailwind CSS. Используй общие `Button`, `Card`, `Badge`, `PageHeader`, `EmptyState`, `Input`, `Select`, `Field`, `Icon`, читая фактические props в исходниках. Системный sans, карточки `rounded-xl`, поля и кнопки `rounded-lg`; токены и интервалы из UI-contract. Не устанавливай библиотеки, не меняй палитру и не подключай внешние шрифты.

Общие типы и моки из `src/lib/**` не меняй. `demoSubjects` — каталог, `demoStudyPlan` — личный пример трёх предметов. Сохраняй исходную согласованность: GPA `3.60`, кредиты 8/5/5, оценки 2 из 3. Предметы и личные оценки не смешивай; изменение каталога в локальном макете не должно менять исходные результаты студента. Для форм кредитов рабочее ограничение README — целое число 1–30.

Если нужны дополнительные локальные моки пользователей, жалоб или журнала, размещай их в `src/components/management/**`, обозначай как примеры и не используй реальные контакты или личные оценки. Если данные должны быть общими — запрос Куралу.

Эти файлы, `/` и страницы Акылбека не меняй. Недостающий общий компонент, реестр или связь в навигации — конкретный запрос Куралу.

Не реализуй backend, БД, API, Server Actions, авторизацию, persistence, настоящую публикацию, изменение прав, начисление баллов, отправку письма или сообщения. Разрешены локальный `useState`, фильтры, формы, валидация и демо-предпросмотр. Не показывай «Сохранено», «Опубликовано», «Роль изменена» или «Баллы начислены» как результат реальной операции. Предпросмотр явно несохраняемый; общий каталог и демоданные не мутируются.

## Работа и проверка

1. Проверь базовый SHA, ветку, `git status` и diff. Не сбрасывай и не перезаписывай чужие изменения; работай в своём checkout.
2. Меняй только свою область. 3–4 ноября заверши шесть MVP-маршрутов, 5–6 ноября — два будущих UI. При риске срыва срока назови Куралу незавершённые страницы и блокирующие общие запросы.
3. Для каждого URL проверь прямое открытие, обновление, переходы и возврат. У активных действий есть понятный локальный результат; неподдержанные операции не маскируются действующими кнопками.
4. Проверь 320/360/768/1024/1440 px. Таблицы могут прокручиваться внутри блока, но не раздвигают страницу. Проверь клавиатуру, видимый фокус, подписи, ошибки и пустые результаты фильтров.
5. Выполни локально `npm run lint` и `npm run build`, передай результат Канату. 7 ноября — интеграция и QA, 8 ноября — исправления и перепроверка.
6. Коммиты и описания — по-русски. Push только после явного разрешения пользователя, PR без запроса не создавай.

Итоговый отчёт: базовый и итоговый SHA, изменённые файлы, статус каждого из восьми маршрутов («каркас / UI реализован / проверен»), проверки, известные ограничения и запросы Куралу. Наличие UI управления не означает готовность backend или всего MVP.
