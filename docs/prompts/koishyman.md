## Дизайн

Строго белый с чёрным и нейтральными серыми оттенками; все пользовательские тексты на русском. Используй примеры таблиц и форм Tailwind CSS, адаптируя их к общему стилю. Без цветных акцентов, градиентов, внешних шрифтов и новых библиотек.

## Содержание страницы

1. Заголовок «Управление» с пояснением о демонстрационном режиме. Ясно покажи, что это интерфейс управления каталогом для будущего администратора или модератора.
2. Таблица или адаптивный список предметов из `demoSubjects`: код, название, кредиты, группа и семестр. Название группы получай из `demoGroups` по `groupId`.
3. Форма предмета: название, кредиты, группа и семестр; код предмета можно показывать дополнительным полем. Число кредитов в рабочем прототипе — целое 1–30 согласно README.
4. Компактное представление групп или контекста выбранного учебного плана, если это помогает понять связь предмета, группы и семестра.

Допускаются статический макет формы или локальная интерактивность: фильтр, переключение группы, раскрытие формы, предпросмотр введённого предмета. Полное поведение будущего каталога не требуется. Если форма выводит результат, используй формулировку «Предпросмотр» и пояснение, что данные не сохраняются. Не добавляй активные кнопки без результата. Можно убрать действие, которое ещё не реализуется, либо явно обозначить его как недоступное.

README различает роли: модератор работает в назначенных группах, администратор создаёт группы и назначает роли. Не показывай выбор административной роли при регистрации и не изображай реальную проверку доступа на этой странице. Если показываешь административный вариант макета, явно обозначь его как демонстрационный.

## Общие экспорты

Из `@/components/ui` доступны:

- `Button`: нативные button props и `variant?: 'primary' | 'secondary' | 'ghost'`; по умолчанию `type="button"`, для отправки формы укажи `type="submit"`.
- `buttonStyles(variant?: 'primary' | 'secondary' | 'ghost')` для `className` на `Link` из `next/link`.
- `Card`: нативные div props.
- `Badge`: нативные span props и `variant?: 'default' | 'strong' | 'outline'`.
- `PageHeader({ eyebrow?, title, description?, action? })`.
- `EmptyState({ title, description, action? })`.
- `Input` и `Select`: нативные props соответствующих элементов.
- `Field({ label, htmlFor, hint?, error?, children })`.

`action` и `children` — `ReactNode`. `Field` создаёт подсказку с ID `htmlFor + '-hint'` и ошибку с ID `htmlFor + '-error'`; `aria-describedby` и `aria-invalid` на поле ставишь ты. `id` поля совпадает с `htmlFor`. Подключай только реально отображаемые подсказки и ошибки. Не используй несуществующие props вроде `asChild` или `size`.

`Icon` из `@/components/ui/icon`: `name` равен одному из `'grid' | 'book' | 'layers' | 'settings' | 'arrow' | 'chevron' | 'check' | 'plus' | 'menu' | 'close' | 'cap'`; есть необязательный `className`.

Общие типы из `@/lib/types`:

```ts
type Grade = 'A' | 'A−' | 'B+' | 'B' | 'B−' | 'C+' | 'C' | 'C−' | 'D+' | 'D' | 'F';
type Subject = { id: string; code: string; title: string; credits: number; semester: number; groupId: string; grade: Grade | null };
type Group = { id: string; name: string; program: string; year: number; subjectCount: number };
type Student = { name: string; initials: string; groupId: string; semester: number };
```

Из `@/lib/demo-data` доступны `demoStudent`, `demoGroups: Group[]`, `demoSubjects: Subject[]`, `demoStudyPlan: Subject[]`, `demoSemesters: number[]`, `gradeOptions: Grade[]` и `demoSummary` с полями `overallGpa: string`, `semesterGpa: string`, `plannedCredits: number`, `gradedCredits: number`, `earnedCredits: number`, `gradedSubjects: number`, `totalSubjects: number`.

`demoStudyPlan` — три предмета каталога с ID `math`, `programming`, `english`. Единый пример для студенческих экранов: A на 3 кредита, B на 2 и предмет без оценки на 3; GPA `3.60`, в плане 8 кредитов, с оценкой 5, зачтено 5, оценены 2 из 3. Остальные предметы каталога без оценок. На странице управления работай с общим каталогом, но не изменяй общие массивы или личные оценки студента.

## Ограничения и готовность

Без API, БД, Server Actions, авторизации, сохранения, localStorage и вычислений GPA. Не создавай таблицы БД, серверные обработчики или настоящую проверку ролей. Локальный `useState` допускается для UI; клиентскими делай только нужные компоненты. Не показывай «Сохранено», «Предмет опубликован» и другие подтверждения серверных действий.

Проверь страницу на 320, 360, 768, 1024 и 1440 px; таблица может прокручиваться внутри своего контейнера, но не должна раздвигать всю страницу. Проверь клавиатуру, подписи полей, фокус и доступность показанных действий. Если добавляешь локальную валидацию, текст ошибки должен быть связан с полем. Если добавляешь фильтр, покажи понятное пустое состояние.

Выполни локально `npm run lint` и `npm run build`. Push и PR без отдельного запроса не делай. В конце передай Куралу краткий отчёт: что готово, какие файлы изменены, какие UI-взаимодействия реализованы, результаты lint/build и известные ограничения. Укажи, что `/management` готова как UI для будущей интеграции; бэкенд сегодня не реализован.
