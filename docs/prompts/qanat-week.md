## 1. Чистый расчёт GPA

Твои исходники в этом срезе — `src/lib/gpa.ts` и `scripts/gpa.test.mjs`. Используй существующий тип `Grade`. Сохрани точный контракт для Акылбека.

```ts
gradePoints: Record<Grade, number>
calculateGpa(subjects: readonly { credits: number; grade: Grade | null }[]): number | null
```

Ключи и значения `gradePoints` берутся из рабочей шкалы README. Взвешивай баллы по кредитам только для предметов с оценкой. `null` исключается из числителя и знаменателя. F даёт 0 баллов, его кредиты входят в знаменатель. Когда оценок нет, возвращай `null`. Сохраняй точность числа, два десятичных знака — задача UI. Функция читает входные данные без мутации и работает без браузера, сессии или API.

Добавь отдельные тесты на пустой массив, план без оценок, неравные кредиты, F, смешанный пример и точность до отображения. Базовый пример A на 3 кредита и B на 2 плюс предмет без оценки на 3 даёт `3.60` в интерфейсе. A на 3 кредита и F на 2 дают `2.40` и 5 кредитов с оценкой, из которых зачтены 3. Последняя разбивка служит также регрессией UI, если модуль GPA возвращает только число. Используй существующий Node test runner и уже установленные инструменты TypeScript.

Передай контракт и SHA Акылбеку через Курала. Акылбек подключает расчёт к текущим оценкам и прогнозу. Если интерфейс разрабатывается параллельно, согласуйте последовательность коммитов. В интеграции должна остаться одна реализация формулы.

## 2. Проверка после интеграции

Проверь все 32 URL из `src/lib/site-routes.ts`. Из них 27 экранов и 5 перенаправлений. Для каждого экрана отметь фактический статус и пройденные сценарии. Для перенаправления запиши цель. `/` ведёт к `/login`. `/competitions`, `/competitions/challenge`, `/achievements`, `/leaderboard` ведут к `/gamification`. Прямые roadmap-макеты проверяй по их согласованному статусу. Основное меню выводит один пункт геймификации.

1. Пройди демо-вход и регистрацию. Валидная форма открывает `/dashboard`. Без профиля появляется диалог имени, фамилии, вуза и группы. Проверь обязательные поля, смену вуза, список групп и клавиатурный фокус. После подтверждения профиль виден в `/profile` и сохраняется при обновлении вкладки. Явный выход и новый демо-вход очищают прежние данные.
2. Пройди меню и прямые URL под `student`, `moderator`, `admin`. У студента «Управление · архив» ведёт в `/management/history`. Прямой `/management` показывает ограничение и ссылку на архив. Модератор и администратор видят управление каталогом. `/management/users` открывается администратору. Архив доступен всем трём ролям. Проверь также `/management/universities` и `/management/programs`.
3. На архиве проверь фильтры года и семестра отдельно и вместе, пустой результат и сброс. В управлении пройди локальное создание, редактирование и архивирование, граничные кредиты 1 и 30 и отказ при недопустимом вводе. У администратора проверь локальное изменение роли записи. Демоданные и текущий ролевой переключатель проверяй как разные состояния. В той же вкладке добавь предмет в управлении, войди студентом и проверь его доступность при новом выборе плана. После изменения каталожных кредитов сверяй существующий результат и архив.
4. На `/subjects` измени оценки, проверь общий и семестровый GPA на «Главной». Сверь `3.60`, кредиты 8/5/5, F, `—` при отсутствии оценок и текущую разбивку по семестрам. Прогноз указывает предположения и оставляет исходные оценки и сводку без мутации.
5. Пройди ссылки, возвраты, обновление, прямые URL и историю браузера. Проверь 320, 360, 768, 1024 и 1440 px, мобильное меню, видимый фокус и поля. Зафиксируй реальные сбои браузера, ложные подтверждения серверного действия и различие между каркасом и завершённым UI.

Запусти `node --test scripts/gpa.test.mjs`, `node --test scripts/site-routes.test.mjs`, `npm run lint` и `npm run build` на проверяемом SHA. Для браузера используй `npm run dev` или `npm start` после сборки. Отмечай среду и выполненные сценарии. Сохраняй скриншоты с маршрутом, ролью и шириной в имени. Серверная регистрация, реальная отправка и выдача полномочий относятся к будущим этапам.
