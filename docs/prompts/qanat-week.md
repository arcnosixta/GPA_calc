## Автоматические проверки

1. Проверь шкалу буквенных оценок по опубликованной таблице, которую использует проект. Для перевода из процентов проверь обе стороны границы каждого диапазона. Если в шкале есть FX и F, проверь их числовые эквиваленты, участие в GPA и зачёт кредитов.
2. Проверь, что GPA использует подтверждённый итоговый процент через буквенную шкалу, а баллы РК1, РК2 и экзамена сохраняются отдельно. Для каждого поля проверь пустое значение, явно введённый ноль и недопустимое значение. Если после интеграции доступна формула с весами, протестируй минимум один пример, вручную посчитанный по опубликованным правилам конкретного вуза или силлабуса.
3. Проверь GPA семестра и всего плана, взвешивание по кредитам, пустой набор оценок, а также отсутствие округления до финального отображения. Контрольные примеры для GPA: A на 3 кредита и B на 2 дают 3.60. F на 3 кредита и B на 2 дают 1.20. Предмет без оценки не участвует в знаменателе.
4. Проверь совместимость с уже сохранённым учебным планом без записей РК. При его чтении должны сохраниться оценки и кредиты. Изменение прогноза должно менять только прогноз.

Используй существующий Node test runner и актуальные экспорты чистого расчёта. Начни с [тестов GPA](../../src/components/student/gpa.test.mjs), [реестра маршрутов](../../scripts/site-routes.test.mjs) и [браузерной проверки](../../src/components/student/browser-check.mjs). Если нужен новый тестовый файл, держи его рядом с проверяемым модулем. Изменение поведения расчёта согласуй с Куралом на конкретном примере из официального источника.

## Браузерная приёмка

На интегрированной версии открой предмет из `/subjects`, внеси РК1 и РК2, проверь результат на странице предмета и сводку на главной. Повтори после перезагрузки, выхода и входа под тем же email. В другом демопрофиле проверь отдельный набор оценок. Проверь семестры с пустыми данными, неизвестный ID предмета и ширину 360 px. Используй вымышленные демопрофили.

Запусти `node --test scripts/site-routes.test.mjs src/components/student/gpa.test.mjs`, новые тесты, `npm run lint` и `npm run build`. Для HTTP-проверки задай `SCHOLARPATH_CHECK_URL` на адрес запущенного сайта. Передай Куралу результаты команд и короткий отчёт с SHA, маршрутами и шагами воспроизведения дефектов. Разделяй ошибки UI, календаря и расчёта.
