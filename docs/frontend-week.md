# ScholarPath: frontend на 2–8 ноября 2026 года

Цель команды — к **8 ноября 2026 года включительно** подготовить связанный frontend на демонстрационных данных. Это план и целевой срок, а не утверждение, что интерфейсы уже готовы или что полноценный MVP будет запущен к этой дате.

В согласованном списке **29 маршрутов**: 5 существующих + 6 авторизации + профиль + 5 новых разделов управления + 7 экранов после MVP + 5 экранов после чатов. Тридцатый маршрут не добавляем ради числа. Уведомления, личные сообщения и другие неподтверждённые возможности этапа 7 сюда не входят.

## Источники и статус работы

- `README.md` сохраняет продуктовый план, роли, правила и порядок релизов. Его этапы не переписываем.
- `src/lib/site-routes.ts` — единый реестр технической карты маршрутов, их групп, этапов и владельцев. Фиксированные URL ниже должны ему соответствовать. При расхождении сообщите Куралу.
- Этот документ уточняет недельную задачу frontend. Наличие страницы для будущего этапа не означает запуск этого этапа или выполнение серверных требований README.
- `docs/ui-contract.md` задаёт общие компоненты и чёрно-белую тему. Недельное распределение владельцев и число маршрутов определены здесь.
- Октябрьские промпты `docs/prompts/akylbek.md` и `docs/prompts/koishyman.md` — исторические инструкции для первых четырёх страниц. Для текущей недели используем файлы с суффиксом `-week.md`.

Курал сохраняет существующие `/`, `/dashboard`, `/setup`, `/subjects`, `/management` и создаёт каркас остальных страниц. Новые минимальные шаблоны, их связи и неактивные формы — архитектурная основа, а не законченный frontend участников. В исходных auth-шаблонах поля и действия отключены или доступны только для чтения; Акылбек отдельно дорабатывает локальные состояния и валидацию.

У каждого маршрута отдельно отмечаем: **каркас → интерфейс реализован → проверен**. HTTP 200 и заголовок подтверждают только доступность каркаса.

## Границы текущего frontend

Чёрно-белая Tailwind-тема, русский интерфейс и существующие общие компоненты сохраняются. Новые библиотеки, внешние шрифты и собственную палитру не добавляем. Локальные компоненты и моки находятся только в области владельца; общие данные не изменяются через локальные формы.

Разрешены локальный UI-state, выборы, фильтры, валидация и явно подписанные демо-предпросмотры. Не делаем backend, настоящую авторизацию, БД, API, Server Actions, persistence, реальную публикацию, начисление баллов, отправку письма или сообщения. Не подключаем расчёт GPA в рамках этой недели: симулятор показывает понятные статические примеры, а не незаявленный вычислительный движок.

Не показываем «Вход выполнен», «Письмо отправлено», «Пароль изменён», «Опубликовано» и подобные подтверждения реальных операций. Состояние успеха можно показать только как отдельно обозначенный **пример состояния**, не результат обращения к серверу. В моках не используем настоящие пароли, чужие контакты и личные оценки. Наличие меню управления не является защитой доступа.

## Общая приёмка

- Все 29 URL существуют, открываются напрямую и после обновления; из общего графа ссылок нет недостижимых экранов и ссылок на несуществующие локальные маршруты.
- Auth-путь связан: вход ↔ регистрация; вход → восстановление → сброс → вход; регистрация → пример подтверждения → вход. Выход и профиль доступны через предусмотренные общие ссылки. Эти переходы не выполняют настоящую авторизацию.
- В каждом подразделе есть осмысленный возврат: цели и симулятор к прогрессу, два примера чатов к списку, задание к соревнованиям, подразделы управления к управлению.
- UI проверен на 320/360/768/1024/1440 px, с клавиатуры, с видимым фокусом и подписанными полями. Таблица может прокручиваться внутри блока, но не раздвигает всю страницу.
- Доступные действия имеют понятный локальный результат; предусмотренные пустые, ошибочные и демонстрационные состояния не обещают backend.
- Исходный GPA `3.60`, кредиты 8/5/5 и прогресс 2 из 3 согласованы на существующих экранах. Моки будущих этапов обозначены отдельно и не раскрывают личные данные других студентов.
- `npm run lint` и `npm run build` проходят на интегрированном коммите. Отчёт содержит проверенный SHA, дату, среду, реальные результаты и ссылки на доказательства. Каркасы не принимаются за законченные страницы.

## Ветки и передача работы

Используем **актуальный `main` после нового архитектурного коммита Курала**. Октябрьская ветка `ui-fundation` не является базой недельной работы. Курал передаёт точный SHA; участники фиксируют его в своём отчёте.

- Акылбек: `student-frontend`.
- Койшыман: `management-frontend`.
- Канат: `qa-frontend` для собственных отчётов и доказательств.

Ветки без префикса `codex/` — согласованное предпочтение пользователя. Каждый работает в отдельной рабочей копии или другом согласованном изолированном checkout. Перед работой проверяет `git status` и diff; не удаляет, не сбрасывает и не перезаписывает изменения коллег. Коммиты и описания пишем по-русски; push только по явному разрешению. PR без отдельного запроса не создаём.

Готовые промпты: [Акылбек](prompts/akylbek-week.md), [Койшыман](prompts/koishyman-week.md), [Канат](prompts/qanat-week.md).
