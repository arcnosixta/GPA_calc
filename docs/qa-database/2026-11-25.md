## Баллы и GPA

Модуль JavaScript выполняет взвешивание десятичных значений в целых единицах и округляет итог один раз. Регрессия проверяет нарушение до изменения и повторное чтение сохранённых баллов после изменения.

| РК1 / РК2 / экзамен | Итог SQL и JS | Результат |
| --- | --- | --- |
| 4.1 / 66.1 / 8.59 | 24 | F, 0.00 |
| 4.1 / 66.1 / 8.6 | 25 | FX, 0.50 |
| 4.1 / 66.1 / 8.61 | 25 | FX, 0.50 |
| 0 / 0 / 0 | 0 | F, 0.00 |
| 0 / 66.1 / пусто | пусто | Нет оценки |
| Пусто / пусто / пусто | пусто | Нет оценки |

Ранее исходный пример `4.1 / 66.1 / 8.6` давал в JS `24 / F` при ожидаемых `25 / FX`. Веса компонентов составляют 30%, 30% и 40%. Набор `assessment-cases.sql` сверяет 49 наборов баллов, включая значения с обеих сторон порога каждой ступени и на самом пороге. Отдельно проверяется отсутствие строки с баллами. Сверка читает сохранённые сырые баллы, итог, букву и числовой эквивалент из `student_results`.

| Записи | GPA | Кредиты с оценкой | Зачтённые кредиты |
| --- | ---: | ---: | ---: |
| A × 3, B × 2, без оценки × 5 | 3.60 | 5 | 5 |
| F × 3, B × 2, без оценки × 5 | 1.20 | 5 | 2 |
| FX × 3, B × 2, без оценки × 5 | 1.50 | 5 | 2 |
| A− × 3, B × 2, без оценки × 5 | 3.402 | 5 | 5 |

SQL-агрегат по сохранённым строкам выступает эталоном для расчёта GPA и зачтённых кредитов. При отсутствии оценок GPA пустой. Промежуточного округления GPA нет.

Отдельная проверка подтверждает сохранение снимка названия и кредитов после изменения и архивирования каталога, сохранение прогноза отдельно от баллов и отсутствие частичной вставки при конфликте в SQL-пакете.

В одноразовом PostgreSQL 18.4 те же миграции применены с локальной заготовкой Auth. Две сессии `psql` с одним `auth.uid()` добавляли один предмет на семестр. Вторая сессия ждала блокировку, что подтвердил `pg_blocking_pids`. После COMMIT первой вторая получила `23505`, а повторное чтение по владельцу, предмету, году и семестру вернуло единственную первую запись с правильным снимком. После ROLLBACK первой прошла вторая вставка. Контрольное чтение вернуло только её ID.

## Права на данные

| Сценарий | Результат в PGlite |
| --- | --- |
| Без входа запросить личный план, баллы, прогноз, профиль и представление результатов | Отказ в доступе к таблицам и представлению |
| Владелец читает план и сохраняет или обновляет баллы и прогноз | Изменения видны владельцу при повторном чтении |
| Другой студент, модератор или администратор запрашивает личную запись по ID | RLS скрывает план, баллы, прогноз и рассчитанный результат |
| Другой пользователь обновляет чужие баллы или удаляет чужой прогноз | Пустой ответ. Проверка под владельцем подтвердила прежние значения |
| Другой пользователь удаляет чужой предмет либо отправляет INSERT/UPSERT для чужого результата | DELETE на личном плане закрыт grant. Политика отклоняет вставку прогноза и UPSERT баллов |
| Владелец меняет владельца, кредиты или снимок названия личного предмета | Отказ при UPDATE, явный владелец при INSERT также отклонён |
| Клиент меняет итоговый балл, букву или эквивалент | Запись защищена grants и вычисляемыми полями |
| Студент меняет каталог, назначения или вызывает RPC смены роли | Изменение каталога скрыто или отклонено. Вставка назначения и смена роли отклонены |
| Модератор меняет план назначенной группы и доступный предмет | Запись разрешена |
| Модератор меняет чужой план, справочник групп или назначение ролей | Чужая вставка отклонена, чужое удаление скрыто. Редактирование свойств группы и назначение роли доступны администратору |
| Администратор назначает модератора и группу | Результат виден получателю назначения. Прямое изменение роли, повышение до admin через RPC и изменение роли администратора отклонены |

Различия проверяются по результату запроса и контрольному чтению. Пустой набор строк при UPDATE или DELETE проверяется повторным запросом под владельцем либо ролью, управляющей каталогом.

## Дефект точности SQL на дробях

На основе `ceb2ab76000ab3f98f183bc6975a69ddb078a6e9` воспроизведён дополнительный случай на границе. Введите РК1 `0.1`, РК2 `0.016666666666666665` и экзамен `61.1625`. Математический итог `24.4999999999999999995` даёт 24/F, что возвращает исправленный JS. Выражение `(rk1 * 30 + rk2 * 30 + exam * 40) / 100` в PostgreSQL 18.4 округляется до `24.500000000000000000` перед вызовом `round`, поэтому результат сохранения — 25/FX. Владелец SQL — Курал. SHA перепроверки после изменения схемы пока отсутствует.
