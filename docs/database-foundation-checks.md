# Проверка основы PostgreSQL и Supabase

Проверено 25 ноября 2026 года для проекта ScholarPath `hygmzyylxejrvobrvcwm` в организации Nurdaulet, регион Frankfurt. При создании сервис вернул стоимость $0 в месяц. Данные подключения находятся в игнорируемом `.env.local`; шаблон имён переменных — `.env.example`.

## Облачная схема

Применены миграции `20261125102600_scholarpath_foundation`, `20261125102620_scholarpath_catalog_seed`, `20261125102817_scholarpath_foreign_key_indexes`. Версии локальных файлов совпадают с историей облачной БД. Типы `src/lib/database.types.ts` сгенерированы из применённой схемы.

В `public` создано 15 таблиц, RLS включён у всех 15. Исходный каталог содержит два вымышленных университета, три группы и шесть предметов. Seed не создаёт Auth-аккаунты или личные оценки.

В живой PostgreSQL выполнена транзакционная проверка с временными тестовыми пользователями и последующим ROLLBACK. Подтверждены student по умолчанию независимо от user metadata, округление дробного итога до 25/FX, изоляция результатов разных студентов, отсутствие доступа администратора к чужим оценкам, запрет самостоятельного назначения admin и отказ модератору в изменении чужого направления. После проверки в Auth осталось 0 аккаунтов, личных записей — 0.

Supabase Security Advisors вернул пустой список. Замечания о недостающих индексах внешних ключей устранены третьей миграцией. В Performance Advisors остаются только информационные уведомления о ещё не использованных индексах новой БД. [Описание уведомления](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index).

## Проверки проекта

- `npm run test:database` — 17 тестов, 17 успешно. Применение всех миграций и повторный seed выполняются в изолированном PostgreSQL PGlite.
- `npm run check:backend` — реальное соединение с облачной БД, версия схемы и отказ в анонимном чтении каталога/профилей подтверждены.
- Существующие шесть тестовых файлов маршрутов, календарей, архива, GPA, личного плана и оценивания прошли после добавления основы.
- Установленный ранее Next.js 16.4.2 остановил сборку из-за известной уязвимости. Для продолжения выполнено обновление до 16.4.6. Остальные предупреждения npm audit относятся к прежней цепочке инструментов ESLint.

- `npm run lint` и `npm run build` — успешно на Next.js 16.4.6.
- На production-сервере `GET /api/backend/health` вернул HTTP 200 с `scholarpath-v1`; `/api/backend/account` без Auth-cookie вернул HTTP 401 с `unauthenticated` и `Cache-Control: private, no-store`.
- HTTP-регрессия всех 33 маршрутов и страницы 404 прошла через новую сборку с Proxy.

## Статус интеграции

Основа БД и серверные контракты реализованы. Текущие формы и студенческие страницы продолжают демонстрационный localStorage-сценарий. Полное прохождение реальной регистрации, подтверждения email, профиля и сохранения баллов в БД входит в задания Акылбека и дальнейшую QA-приёмку Каната. Первый настоящий администратор назначается владельцем по инструкции в `docs/database-plan.md` после появления своего Auth-аккаунта.
