# Как начать совместную работу

## Общая исходная версия

Курал подготовил основу в ветке `codex/ui-foundation`. Перед запуском агентов обе копии проекта должны получить именно эту основу: общие компоненты, демоданные, маршруты и документацию. Один текст промпта без файлов основы недостаточен.

Путь `/home/arcnosixta/GPA_calc` в документах — расположение проекта у Курала. Участники работают в своих копиях; на другом компьютере используйте местный путь.

Если основа уже доступна в локальной ветке, в собственном клоне создайте свою рабочую ветку от неё:

```bash
# Акылбек
git switch -c codex/student-ui codex/ui-foundation
```

```bash
# Койшыман — в своей копии проекта
git switch -c codex/management-ui codex/ui-foundation
```

Не переключайте ветки друг другу в одном рабочем каталоге. Если оба агента запущены на одном компьютере, используйте отдельные клоны или worktree. Оба участника могут начинать одновременно после получения основы.

## Передача основы через patch

Для передачи без публикации ветки Курал может отдать файл `scholarpath-ui-foundation.patch`, содержащий только коммиты основы. Получатель применяет его в чистой отдельной копии исходного проекта на базовой версии, указанной в переданном отчёте:

```bash
git switch -c codex/ui-foundation
git am /путь/к/scholarpath-ui-foundation.patch
```

Если копия уже содержит эти изменения, повторно patch не применяйте. Если `git am` сообщает конфликт, остановитесь и передайте Куралу сообщение; не исправляйте общую основу параллельно в каждом клоне.

## Промпты агентам

Скопируйте весь текст соответствующего файла в чат своего агента:

- Акылбеку: [prompts/akylbek.md](prompts/akylbek.md).
- Койшыману: [prompts/koishyman.md](prompts/koishyman.md).

Оба промпта ссылаются на [общий UI-контракт](ui-contract.md). Заглушки страниц участники заменяют в своей области. Главная `/` — готовый образец оформления и часть каркаса Курала.

## Возврат результата

Участник передаёт Куралу свою ветку или коммиты, список изменённых файлов, результаты lint/build и известные ограничения. Публиковать ветку или PR автоматически не требуется. Курал интегрирует студенческие страницы и управление, разрешает пересечения в общих компонентах, проверяет общий lint/build.

После интеграции Канат проходит [ручной чеклист](qa.md). Он присылает воспроизводимые ошибки, владельцы исправляют их, Канат повторяет проблемный сценарий. Готовность каркаса и стартовых заглушек не засчитываем как готовность четырёх итоговых страниц.
